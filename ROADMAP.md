# Roadmap and decisions

The one place that remembers what we decided and what is still to do. Update it whenever
something is added, changed or decided. (Last updated: 7 Nov 2026.)

## How the site works (decisions we made)

- Home page is an explorable parallax star map: each section and project is a star, with a
  plain navbar label and a themed subtitle ("origin", "the observatory", "instruments"...).
- Look: crisp dark sky, Milky Way made of tiny stars, faint corner colour glows, sharp stars
  with spikes. No smoky nebula (it looked blurry).
- Deployed on GitHub Pages as a static export (no server). No custom domain yet.
  - Site address: `https://alca1206.github.io/cosmic-intelligence-lab/`
  - Branch is `master`. Push with git (`git add -A`, `git commit`, `git push origin master`).
  - Do not upload files one by one in the GitHub web page: it caused stale files and failed builds.
  - `.github/workflows/deploy.yml` must be replaced by hand (it cannot be written remotely).
- Adding a project = one entry in `data/projects.ts` (template at the top of the file).
- Adding a how-it-works demo = one entry in `data/demos.ts` (rules at the top of the file).
- Adding a live lab = an entry in `data/labs.ts` plus its component in the `labViews` list in
  `app/playground/[slug]/page.tsx`. Its project's Playground page then gets a "Try it" tab.
- Only state what a project's README or code supports. No guesses, no made-up links or numbers.
- Real numbers are labelled "real"; made-up example values must be labelled "illustrative".
- Internal links must use Next's `Link` (the plain `Button` component does not add the GitHub
  sub-folder prefix).
- Page changes are checked at desktop and phone width, and with the build run both at the root
  and with `NEXT_PUBLIC_BASE_PATH=/cosmic-intelligence-lab`.

## Playground plan

Everything interactive lives in the Playground tab; each project page links to its demo.
One card and one page per project: `/playground/<project slug>`, with tabs "Try it" (a live lab,
`data/labs.ts`) and "How it works" (a walkthrough, `data/demos.ts`). The tab is in the address
(`#try`, `#how-it-works`). A project gets a card as soon as it has either. The calibration
experiment stays its own card (it belongs to no project). Old addresses
`/playground/house-price-model` and `/playground/house-price-prediction` redirect to the new page.

Done:
- Gallery page `/playground` with one card per project.
- Confidence calibration experiment (`/playground/calibration`).
- PaperPilot walkthrough, first pass, and its live chunking lab (see "Next" item 1).
- House-price walkthrough (the "How it works" tab): comet map (violet-to-rose, chosen over cyan, gold and pale), 7 steps, real code
  from the repo (pinned commit), real numbers, real training-loss chart.

- Live house-price model (the "Try it" tab; one compact screen: sliders left, price on top, network bars and what-if curve side by side on wide screens): the real trained weights run in the
  browser (exported by `scripts/export_house_model.py` into `public/ml/house-price-model.json`);
  sliders change the inputs, the price and the firing neurons update live, plus a what-if curve.
  Weights stay fixed when using the model; only activations change. The neuron panel shows
  one bar per neuron (this house) over the average of all 21,613 houses, with "a typical house
  fires 27 of 64"; the averages are real and stored in the model file. Matches the Python model
  within $2 on 5 reference houses (tested). Re-run the script if the model is retrained.

Next (in this order):
1. PaperPilot: first pass DONE (`/playground/paperpilot`): 8 steps, 7 stages, real code from the repo
   (pinned commit e982acd, `data/paperpilot-source.ts`, generated by pattern so line numbers are exact),
   real settings (800-char chunks, top 4, 0.35 threshold). Example paper, scores and answer are
   labelled "illustrative" because Ollama was not run. The refusal (Gate 1) is step 6.
   LIVE LAB BUILT (the "Try it" tab): (1) chunking playground, running a TypeScript port of the real
   chunker (`lib/ml/paperpilot-chunking.ts`, tested against output of the Python code); (2) refusal-gate
   lab (question list, threshold slider, top-4 chunks, recorded answer), which APPEARS ONLY when
   `public/ml/paperpilot-demo.json` exists. The owner makes it with `scripts/export_paperpilot_demo.py`
   (needs Ollama; paper must be OK to republish; a questions.txt about that paper). Same run turns the
   walkthrough into "recorded". Possible later: type your own question using the real embedding model
   in the browser (transformers.js, a few hundred MB download, optional button).
   To make the walkthrough "recorded": the owner runs PaperPilot once on a paper with two questions (one answerable,
   one off-topic) and sends the chunk count, the scores, the answer and the page numbers; then replace
   the example values and set `kind: "recorded"`.
2. Pneumonia CNN walkthrough: image through the layers, probability, threshold trade-off,
   Grad-CAM heatmap. Needs one logged real run on one X-ray.
3. Handwritten digit drawing demo (draw a digit, see the prediction live; small model).
4. Training replay with real weight snapshots (shows weights actually changing). Needs a new
   training run of the house-price model with `training_logger.py` saving snapshots every few
   epochs. The notebook only recorded the loss.
5. "Why I did it" notes next to each demo, so a recruiter understands the decisions at once.
